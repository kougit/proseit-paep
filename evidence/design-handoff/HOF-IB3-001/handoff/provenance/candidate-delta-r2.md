## 1. Why renders changed

Two decisions contradicted the rendered candidate, so the affected render set was regenerated:

| Decision | What the candidate showed | What revision 2 shows |
| --- | --- | --- |
| X-05 option B | Active language only in the account menu (option A) | With more than one locale, a topbar language (globe) control at ≥ 600 px showing the active language code, accessible name "Language: {language}"; below 600 px the language group stays in the account menu. With one locale, no control |
| RD-01 (16 px edge margin) | Menus and panels kept 8 px from the viewport edge below 600 px; SCR-SHELL-023 board text said 8 px | 16 px (`--paep-space-4`) everywhere; board text and specimens say 16 px |
| RD-02 (inset 24 rem panel) | Already rendered as an inset panel at 24 rem, but at 8 px inset below 600 px | Inset at 16 px; the prose that said "26 rem" and "full screen" is corrected |
| §3 tokens | Reference CSS declared the `--paep-shell-content-max-inline-size` alias and raw z-index numbers | Alias removed (`--paep-layout-content-max` used directly); six `--paep-layer-*` tokens declared and used. No visual change |
| X-01 | Rail labels used automatic hyphenation | `hyphens: manual`; labels wrap unless an authored `shortLabel` exists. Any rail render affected is inside the regenerated set in §2 |

No other visual intent changed. Q-01..Q-14 were all decided as the recommended option A, which the candidate already showed.
